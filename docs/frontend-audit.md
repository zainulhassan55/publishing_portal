Plus ~700 lines of hand-written CSS utility classes: `.btn` + 6 variants, `.card`, `.card-quiet`, `.card-cover`, **12 `.portfolio-tone-*` pastel gradients** ([:421-467](src/index.css#L421-L467)), `.badge`, `.meta`, `.section-y`, `.metric-strip`, `.field`, `.surface`, `.hero-panel`, `.section-rule`, `.site-nav-link`, `.series-tab`, `.article-row`, `.service-tile`, `.home-hero-*` (8 classes), `.journal-carousel-*`, 3 keyframe animations.

**Problems with the token layer:**
1. No neutral grey ramp — components fall back to Tailwind's `slate-*` (`slate-300/400/500/600/700/800`) mixed with the custom `ink-*`. Two competing greyscales.
2. No type scale. Sizes are magic values: `text-[1.85rem]`, `text-[2.1rem]`, `text-[2.65rem]`, `text-[2.45rem]`, `text-[1.65rem]`, `text-[1.15rem]`, `text-[1.05rem]`, `text-[1.02rem]`, `text-[0.98rem]`, `text-[11px]`, `text-[10px]`. Headings therefore don't feel systematic.
3. No spacing scale beyond Tailwind defaults; section padding is one class (`.section-y`).
4. No semantic colors (success / warning / danger / info), no OA-status colors, no article-type colors.
5. Shadows are inline magic values repeated verbatim in 9 files (`shadow-[0_8px_22px_rgba(7,19,31,0.04)]`).
6. No dark-mode tokens.

## 6. Assessment — what reads as "not professional"

Ranked by how much damage each does to perceived credibility.

### 6.1 Credibility blockers (fix regardless of redesign)

1. **The literal string `ISSN Sample` is rendered on every journal card and every journal masthead.** [journalTemplate.ts:918,934-935](src/data/journalTemplate.ts#L918), [PortfolioCard.tsx:69](src/components/shared/PortfolioCard.tsx#L69), both book series files. To a researcher or an indexing service this single detail says "not a real publisher". Either show real ISSNs or show "ISSN: applied for" / omit the field.
2. **Google Scholar cannot index this site.** There are no Highwire Press / Dublin Core citation meta tags (`citation_title`, `citation_author`, `citation_journal_title`, `citation_doi`, `citation_pdf_url`), no JSON-LD (`Periodical`, `ScholarlyArticle`), and because it is a client-rendered SPA, no per-URL `<title>` or `<meta description>` at all — all 263 URLs serve the single static head from [index.html](index.html#L16). For a journal portal this is not cosmetic; it is the difference between articles being discoverable and invisible.
3. **No search. Anywhere.** No header search, no search page, no results page, no faceting. Every reference publisher treats search as the primary header element. This is the biggest *functional* gap on the site.
4. **Visible dead controls.** `FilterBar` pills look like filters and do nothing (`/articles`, `/news`, `/proceedings`, `/special-issues`). The contact form has no `onSubmit` and submits via `<a href="#">` ([ContactPage.tsx:830-858](src/pages/ContactPage.tsx#L830-L858)). "Download PDF" points to `#`. The article "Reader actions" panel lists *"Download PDF / Copy citation / View related articles"* as plain `<p>` text ([ArticleDetailPage.tsx:274-278](src/pages/ArticleDetailPage.tsx#L274-L278)). Users click these. Nothing happens. This is the fastest way to lose trust.
5. **404s silently redirect to the homepage** ([App.tsx:56](src/App.tsx#L56)). Bad for users, bad for SEO (soft-404), and it hides broken links from you.

### 6.2 Visual-language problems (the "feel" the user described)

1. **A dark navy hero on every single page.** `PageHero` (10 pages) and `JournalMasthead` both render a full-bleed `#07131f` panel with a teal radial glow and a 48px grid overlay. That treatment is the visual signature of a B2B SaaS landing page, not a publisher. Elsevier, Springer, Wiley and T&F all use **light mastheads** with a thin brand bar, strong typographic hierarchy, and the journal cover image as the only large visual. Repeating a dramatic dark hero on *Policies*, *Indexing* and *Guidelines* is the main reason the site doesn't read as scholarly.
2. **Decorative effects that signal "template".** Hero film grain + 18s `drift` scale animation + 1.6s crossfade ([index.css:149-193](src/index.css#L149)); card hover lift `translateY(-3px)` with a growing shadow on *content* cards; article rows that slide `translateX(4px)` on hover; `.service-tile` with a 2px teal top border. Academic interfaces earn trust through stillness and density, not motion.
3. **12 arbitrary pastel gradients** (`mint`, `sky`, `sage`, `sand`, `slate`, `seafoam`, `azure`, `olive`, `cyan`, `emerald`, `amber`, `steel`) assigned per-slug with no semantic meaning ([index.css:421-467](src/index.css#L421-L467)). They read as a design-template palette. Journals should be differentiated by **their cover artwork and their subject label**, not by pastel chrome; if you want colour-coding, code it to *subject area* (a fixed, documented set of 6–8), not to slug.
4. **Justified body text** (`.prose-justify`, [index.css:85-90](src/index.css#L85-L90)) applied to journal pages, book pages, catalogue pages. Browser justification without proper hyphenation dictionaries produces rivers of white space; it also hurts readers with dyslexia. No major publisher justifies web body copy. Remove it.
5. **Typeface register is wrong.** Figtree is a friendly geometric sans (fintech/startup register). Newsreader is a good scholarly serif and worth keeping. Reference set: Elsevier uses a neutral grotesque; Springer uses Lato/Source Sans; Wiley uses Open Sans; T&F uses Mulish. An institutional pairing would be e.g. **Source Serif 4 / Newsreader** for headings + **Inter, Source Sans 3 or IBM Plex Sans** for UI and body.
6. **No consistent reading measure.** Journal overview paragraphs sit in a `1.4fr` column inside a 1280px container — roughly 80–95 characters per line at desktop width. Long-form should be capped at **66–75ch**.
7. **Rounded corners too large for the genre.** `--radius-lg: 16px`, `--radius-xl: 20px`, `rounded-2xl` on content panels. Publisher UIs sit at 2–6px, and prefer 1px rules over shadows.
8. **Contrast failures.** `text-slate-400` (#94a3b8) on white ≈ **2.6:1** — well below the 4.5:1 AA threshold, and it is used for visible label text: service numbers, "Our values" numbers, and the "Frequency"/"Review" labels on every journal and book card ([PortfolioCard.tsx](src/components/shared/PortfolioCard.tsx), [PublisherServicesSection.tsx](src/components/home/PublisherServicesSection.tsx), [AboutPage.tsx](src/pages/AboutPage.tsx)). Separately, the `.meta` class (#64748b) lands at ≈4.8:1 on white and ≈4.5:1 on `--color-paper-soft` — technically passing, but at 11px with 0.14em tracking it has no margin, so any surface tint darker than `#f7f9fb` pushes it under.

### 6.3 Information-architecture problems

1. **Author-critical pages are buried.** *Guidelines*, *Policies*, *Call for Papers*, *Indexing*, *News* live only in an 11–12px dark utility strip (and only the first 4 of 7 show on desktop, [SiteHeader.tsx:48](src/components/layout/SiteHeader.tsx#L48)). Publishers give these audience-based top-level entries — **For Authors / For Reviewers / For Editors / For Librarians** — usually as mega-menus.
2. **No breadcrumbs.** On a 263-URL site with 3 levels of nesting (`/journals/ijdh/author-instructions`), breadcrumbs are mandatory for orientation and for SEO.
3. **The journal subnav is hard to use.** Four click-to-open dropdowns containing 22 destinations, triggered by a text `▼` glyph, with no arrow-key navigation, no `role="menu"` semantics, and `sm:relative` positioning that goes full-width on mobile. For a journal micro-site, the standard patterns are either (a) a persistent left sidebar nav on all journal sub-pages, or (b) a horizontal bar with a single grouped mega-panel.
4. **"On this page" is a chip cloud, not a TOC.** It only renders when a page has >3 blocks, it is not sticky, and it has no scroll-spy. Long author-instruction pages need a sticky TOC with active-section tracking.
5. **No issue-centric browsing.** `JournalArchivePage` shows flat `FeatureCard`s with one stub issue per journal. Real archives drill **year → volume → issue → issue TOC grouped by section** (Editorial / Research Articles / Reviews).
6. **The article page is a stub.** No full text, no PDF viewer, no references, no author affiliations/ORCID, no received/accepted dates, no license badge, no CrossMark, no citation export (BibTeX/RIS/EndNote), no metrics, no supplementary material, no "How to cite", no related articles. On a publisher site the article page **is** the product.
7. **`BookSeriesLayout` duplicates `JournalLayout`** almost line for line (162 vs 167 lines) instead of sharing a `PublicationLayout`.
8. **Zero published content, and the design doesn't account for it.** `latestArticles: []` and `articleDetails: []` mean the Articles page, the article detail route, and the home "Latest articles" block all render placeholder copy ("No articles published yet", "Articles coming soon"). A new publisher's homepage cannot be article-density-driven — but right now it apologises for being empty in three places. The redesign needs a composition that is **credible while empty** (scope-led, portfolio-led, standards-led) and that gracefully upgrades as content arrives.

### 6.4 Accessibility gaps

- No skip-to-content link; `<main>` has no `id`/`tabIndex`
- Dropdowns: `aria-haspopup="true"` without `role="menu"`/`menuitem`, no arrow-key or Home/End handling, no focus return on close
- Hero carousel: `aria-pressed` on markers (should be a tablist or labelled dots), no `aria-live` region, auto-advances every 7s with no pause control (WCAG 2.2.2)
- `:focus-visible` is defined for `.btn` and `.home-hero-marker` only — not for nav links, card links, subnav tabs, or anchor chips
- `text-align: justify` + `hyphens: auto` on body copy
- Contrast failures listed in §6.2.8
- Journal carousel is scrollable but has no keyboard affordance beyond native scroll

### 6.5 Performance gaps

- 3 full-size hero JPEGs decoded on first paint, all eager, no `srcset`, no AVIF/WebP, no `fetchpriority`
- 10 journal cover JPEGs loaded eagerly in the home carousel; no `loading="lazy"` anywhere in the codebase
- No route-level code splitting (`React.lazy`) — the 960-line journal template and all 10 journal specs are in the initial bundle
- Google Fonts via two `<link>`s (render-blocking); no self-hosting, no subsetting
- No SSR/prerender, so first meaningful paint for a 22-page-deep journal policy page requires the full JS bundle

## 8. The submission system — current state and the decision you have to make

**Current state:** there is no submission UI in this app. Six links hand the user to an OJS install ([src/lib/ojs.ts](src/lib/ojs.ts)): `VITE_OJS_URL` is `http://localhost:8000` in dev and `https://www.nextgeniqpress.com/ojs` in VPS mode. The moment an author clicks "Submit manuscript", they leave your design system and land in stock OJS. That discontinuity is a large part of why the product doesn't feel like Elsevier or Springer — those publishers run a visually continuous journey from journal page → submission wizard → author dashboard.

Three options, with honest trade-offs:

| | **A. Theme OJS** | **B. Portal-native wizard on the OJS REST API** | **C. Hybrid (recommended)** |
|---|---|---|---|
| What you build | An OJS child theme (PHP + Smarty + LESS) matching the new tokens | React submission wizard, author dashboard, reviewer workspace calling `/api/v1/*` | B for **author-facing** flows; A (light) for editor/reviewer back office |
| Effort | Low–medium | High | Medium–high |

**Recommendation: C.** Build in-portal, on-brand: (1) a 7-step submission wizard, (2) an author dashboard with a status timeline, (3) a reviewer invitation/review-form workspace. Leave editorial desk work in a lightly themed OJS. Spec for the wizard steps:

1. **Journal & section** — journal picker (pre-filled when entered from a journal page), section, special-issue selector
2. **Requirements checklist** — the OJS submission checklist as explicit checkboxes, plus scope confirmation
3. **Metadata** — title, running title, abstract (word counter), keywords (3–8, chip input), language, subject categories
4. **Authors** — repeatable author rows: name, email, affiliation (ROR lookup), country, ORCID (validated), corresponding-author radio, contribution roles (CRediT taxonomy), drag to reorder
5. **Files** — drag-and-drop upload with per-file *type* tagging (manuscript / anonymised manuscript / title page / figures / tables / supplementary / cover letter), size/format validation, progress, re-order, delete
6. **Declarations** — funding (with funder lookup), conflicts of interest, ethics approval + consent, data availability statement, generative-AI use disclosure, preprint status, suggested & opposed reviewers
7. **Review & submit** — full read-back, per-step edit links, submit → confirmation screen with submission ID, what-happens-next timeline, and an email receipt

Then **author dashboard**: submissions table with status chips (Submitted → Under review → Revisions requested → Resubmitted → Accepted → In production → Published), per-submission timeline, decision letters, revision upload with a response-to-reviewers editor, co-author visibility, proof approval.

And **reviewer workspace**: invitation accept/decline with due date, blinded manuscript access, structured review form (recommendation + per-criterion scores + comments to author + confidential comments to editor + file upload), saved drafts, completed-review history.

## 9. What to keep

Do not throw these away in the redesign:

1. **The journal template system** ([journalTemplate.ts](src/data/journalTemplate.ts)) — one `JournalSpec` → 22 consistent pages. This is better than most small publishers manage, and the prose (ethics, AI policy, data policy, reviewer guidelines, APC) is publisher-grade.
2. **The content model** ([types/content.ts](src/types/content.ts)) — `ContentBlock` / `JournalPage` / `JournalMenuGroup` is a sound structure; extend it rather than replace it.
3. **The route shape** — layout routes with outlet context for journals and series is the right architecture for micro-sites.
4. **The information coverage** — 22 journal pages, 4 publisher policies, CFPs, special issues, indexing, proceedings. The *information architecture inventory* is close to complete; it's the presentation layer and the missing search/article/submission surfaces that need work.
5. **`CatalogPage`** as a concept — a page-level template driven by data. Generalise it rather than delete it.

## 10. Summary — the eight things that will change the perception most

1. Replace the dark SaaS hero system with a **light, typographic, institutional masthead** system.
2. Add **search with faceting** as the primary header element.
3. Build a **real article page** (full text, PDF, citation export, references, declarations, metrics).
4. Build the **in-portal submission wizard + author dashboard**.
5. Add **per-page SEO + Google Scholar citation meta + JSON-LD** (and prerender or SSR the public pages).
6. Build a **proper design-token layer** (grey ramp, type scale, spacing, semantic colours, 2–6px radii, 1px rules over shadows) and a **primitive component library** on top of it.
7. Remove every **dead control** and every **placeholder string** (`ISSN Sample`, `#` links, decorative filter pills, non-submitting form).
8. Replace justified text, pastel slug-gradients, hover lifts, grain and drift animations with **stillness, density and a 66–75ch reading measure**.
